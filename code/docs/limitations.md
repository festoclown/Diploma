# Статус, ограничения и следующие шаги

## Что пока не проверено выполнением

При подготовке и переработке проекта не запускались NIP-разбор, тесты, установка, загрузка корпусов и моделей или эксперименты. Выполнены статическое чтение исходников и сверка документации API. Поэтому совместимость CUDA-среды и численные выводы ещё не подтверждены.

Перед длинными сериями нужен ручной цикл: установка → тесты → пилот → просмотр manifest/таблиц → исправление обнаруженных ошибок → фиксация среды и протокола. Если первая установка потребует согласования версий зависимостей, сохраните итоговый lock-файл. Зафиксированная версия NIP 0.12.4 опубликована в PyPI; это не утверждение о проверенной совместимости всего окружения.

## Статистические ограничения

1. **M6 — эвристика.** SD bootstrap-разности не является автоматически доверительным интервалом, тестом значимости или гарантией неухудшения. Число кандидатов и выбор лидера по L влияют на поведение метода.
2. **Покрытие не идентифицируется по одним наблюдённым классам.** Истинное coverage считается только для анализа. Bootstrap не может породить отсутствующий в L класс.
3. **Вырожденный ARI.** При одной метке/одних singleton-группах высокие значения могут мало говорить о полезной структуре. Такие случаи сохраняются и анализируются отдельно; основной результат не скрывает их fallback-ом.
4. **Условные интервалы.** Bootstrap по 30 повторам относится к получению меток на одном корпусе. Он не учитывает все источники вариации данных, эмбеддингов и выбора модели.
5. **Групповая зависимость.** У 20 Newsgroups учитываются связи, извлечённые из заголовков. Неизвестные почти дубликаты в любом корпусе могут сохраниться. Group bootstrap использует только размеченную часть известной группы.
6. **Перенос M4.** Единственная lambda настраивается на синтетике. Плохой результат на текстах может говорить о сдвиге домена. Нельзя после этого незаметно подобрать другую lambda на тех же тестовых метках.
7. **Малое число реальных наборов.** Digits и Dry Bean дают быструю числовую проверку; Breast Cancer — только малую двоичную диагностику, три текстовых корпуса — проверку переноса. Разметка отражает заданную таксономию и не измеряет напрямую полезность тем для человека.
8. **Внутрипуловый oracle.** Малый regret не означает высокое абсолютное качество: весь пул может быть плохим. Всегда показывайте ARI рядом с regret.

## Границы базовой реализации

| Есть сейчас | Отдельная последующая работа |
|---|---|
| M0–M7, bootstrap, E1/E2/E4-диагностика | Теоретическое обоснование допуска M6 |
| CSV и парные интервалы | Подтверждающие p-values и поправка Holm после фиксации семейства тестов |
| Cosine silhouette и Euclidean DB | Другие внутренние индексы и их калибровка |
| Основной MiniLM | Сравнение эмбеддеров, устойчивость при их замене |
| Идеальные метки симулятора | Эксперименты с шумом 10/20% |
| c/tau/DB/fallback на текстах | Готовые конфиги всех дополнительных синтетических абляций |
| Метки классов | Парные экспертные ограничения и их стоимость |
| Статические сохранённые векторы и CUDA-путь для дорогих операций | Обучение эмбеддера или кластеризации по меткам |
| Exact dedup и известные discussion groups | Полный аудит почти дубликатов |

Дополнительные seeds KMeans 43/44 технически задаются в `candidates.seed`, но это отдельные новые пулы. При M4 изменение пула потребует отдельного development-контракта. CPU и CUDA используют разные файлы веса: `frozen_mixture.json` и `frozen_mixture_cuda.json`.

HDBSCAN вводит ещё один выбор протокола: `-1` означает шум. Порог покрытия 70% и штраф внутренних индексов нужно проверять в анализе чувствительности. Даже при одинаковых параметрах CPU и cuML могут дать разные разбиения; расхождение нельзя автоматически считать ошибкой. Плотная матрица расстояний имеет O(n²) памяти и ограничивает масштабирование. CUDA-путь не проверялся на A100; заявлять измеренное ускорение пока нельзя.

Не реализованы permutation-тест кластерной тенденции, causal features, интерпретация residual-векторов и схемы top-k/RBO из прежних тем. Они не являются частью выбранного минимального протокола.

## Технические ограничения

Сетевые загрузчики требуют доступных внешних источников и, при необходимости, настроенного пользователем доступа Hugging Face. Они не обходят ограничения сервисов. Ревизии AG News, Banking77 и модели записываются при загрузке; для 20 Newsgroups фиксируются версия sklearn, параметры очистки и checksum выгруженных записей.

`source_revision` для 20 Newsgroups не выбирает новую версию архива: используется датасет, предоставляемый sklearn. В основной конфигурации это поле оставлено одинаковым для общей текстовой сетки; реальный источник записан отдельно.

Кеши проверяют соответствие файлов и параметров, но не служат системой миграций между версиями кода. Не запускайте одинаковые стадии на одном каталоге параллельно. Не удаляйте старые результаты автоматически при исправлении программы; сохраните их как невалидные/предыдущие и заведите новую серию.
