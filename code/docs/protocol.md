# Протокол и математическая постановка

## 1. Что выбираем

Пусть есть объекты $X=(x_1,\ldots,x_n)$ и скрытые классы $y=(y_1,\ldots,y_n)$. Для текста $x_i$ — нормированный эмбеддинг документа. Сначала **без меток** строим конечное множество разбиений $\mathcal P=\{P_1,\ldots,P_M\}$. Каждый кандидат содержит номер кластера для каждого из n объектов.

Например, кандидат — результат KMeans с K=16. Это готовое разбиение всего корпуса. Мы выбираем один такой вариант. Внутренний индекс оценивает его геометрию, а частичный внешний индекс — соответствие небольшой доступной разметке.

Векторы всех объектов доступны заранее. Метки разделяются на резерв S и проверочную часть T. В одном повторении из S раскрываются метки подмножества L, $|L|=m$. Проверочные метки T становятся доступны оценщику только после того, как все методы выбрали кандидатов. Это трансдуктивная оценка выбора разбиения, а не тест классификатора на будущих документах.

## 2. Данные и модели

### Синтетика

Основные наборы имеют $n=2000$, $d=10$ и восемь классов. Для трёх гауссовых геометрий центр класса $k$ равен $\mu_k=a e_k$.

| Геометрия | Параметры | Что проверяет |
|---|---|---|
| separated | $a=6$, ковариация $I$ | Хорошо разделённые компактные группы |
| overlapping | $a=3$, ковариация $I$ | Перекрытие соседних групп |
| elongated | $a=6$, ковариация $Q_k\operatorname{diag}(9,1,\ldots,1)Q_k^\top$ | Вытянутые группы; $Q_k$ задаётся QR-разложением |
| moons | Четыре пары сдвинутых двумерных полумесяцев; остальные измерения содержат слабый шум | Невыпуклая форма, где центроидный алгоритм может ошибаться |

Баланс: либо равные численности, либо вероятности $p_k\propto2^{-k/2}$. Численности округляются методом наибольших остатков. Development для M4 по-прежнему использует 18 наборов: три гауссовы геометрии × два баланса × seeds 0,1,2. CPU confirmation использует 60 наборов; расширенная GPU confirmation добавляет moons и содержит 80 наборов. Успех на moons — отдельная проверка, а не часть настройки M4.

### Быстрые числовые наборы

| Данные | Размер до ограничения | Основная роль |

| [Dry Bean](https://archive.ics.uci.edu/dataset/602/dry%2B) | 13 611 объектов, 16 измеримых признаков, 7 классов | Более интерпретируемые табличные признаки; случайная подвыборка 4 000 |
| [Breast Cancer](https://scikit-learn.org/stable/modules/generated/sklearn.datasets.load_breast_cancer.html) | 569 объектов, 30 признаков, 2 класса | Только дополнительная проверка на двоичном и малом наборе; бюджеты 20 и 50 |

Для встроенных наборов scikit-learn не нужна сеть. Dry Bean загружается отдельной явной командой с сайта UCI; архив проверяется и подготовленная копия хешируется. Точные совпадения числовых строк удаляются; строки с одинаковыми признаками и конфликтующими метками исключаются. До разбиения на S и T признаки стандартизируются **без использования меток**. Это разрешено трансдуктивной постановкой и должно быть указано при интерпретации результата. Digits и Dry Bean образуют основную табличную серию; двоичный набор служит диагностикой и не смешивается с ней при выводе о покрытии многих классов.

Это исследовательский выбор, а не доказательство, что 50 компонент оптимальны. GPU-конфиг выполняет кодирование и PCA на CUDA.

## 3. Пул кандидатов и вычислительное устройство

Используются три семейства: **KMeans**, **HDBSCAN** и **спектральная кластеризация**. Average linkage удалён из нового протокола. Основная сетка содержит семь KMeans-разбиений при $K\in\{2,4,8,16,32,64,128\}$, четыре спектральных разбиения при $K\in\{4,8,16,32\}$ и три HDBSCAN-разбиения при min_cluster_size=20,50,100 и min_samples=10 в семантике scikit-learn. В cuML передаётся 9: cuML исключает саму точку из подсчёта min_samples, а scikit-learn включает её. Итого до **14 исходных кандидатов** до удаления совпадающих и непригодных вариантов. Для технического пилота сетка меньше.

KMeans и HDBSCAN используют евклидову геометрию признаков для построения. Спектральный метод использует граф 15 ближайших соседей. На GPU вызываются реализации [cuML KMeans](https://docs.rapids.ai/api/cuml/stable/api/generated/cuml.cluster.KMeans/), [cuML HDBSCAN](https://docs.nvidia.com/cuml/latest/api/generated/cuml.cluster.hdbscan.HDBSCAN/) и [cuML SpectralClustering](https://docs.rapids.ai/api/cuml/stable/api/generated/cuml.cluster.SpectralClustering/); на CPU — соответствующие алгоритмы scikit-learn. Настройка compute.backend в NIP явно выбирает cpu или cuda. Автоматического незаметного переключения на CPU при ошибке CUDA нет.

HDBSCAN может пометить часть объектов значением -1, означающим **шум, а не кластер**. Кандидат пропускается, если назначено менее 70% объектов или если среди назначенных не образовались хотя бы два кластера. Все такие случаи записываются в manifest пула. У KMeans и спектрального метода назначены все объекты. Совпавшие полные разбиения объединяются; ID — SHA256 канонического списка меток, отсортированные ID определяют разрешение равенств.

На CUDA исходная матрица признаков, PCA, кандидаты, одна общая матрица расстояний float32 и расчёт внутренних индексов остаются на GPU. Плотная матрица для 4 000 объектов требует примерно 64 MB без промежуточных массивов. Это ускоряет тяжёлую часть, но не устраняет квадратичную сложность расстояний. На CPU выполняется тот же расчёт через NumPy/scikit-learn. Разбиения CPU и GPU **могут отличаться** из-за реализаций, точности и разрешения равных расстояний; backend сохраняется в идентичности пула и результатах. Их следует сравнивать как разные реализации протокола, а не требовать побитового совпадения.

## 4. Внутренние и внешние оценки

Внутренний индекс $I(P)$ вычисляется по всем векторам без истинных меток. Основной — silhouette, где больше лучше. Для текстов расстояние косинусное, для синтетических и числовых данных евклидово. Дополнительный индекс — Davies–Bouldin (DB) на евклидовых расстояниях, где меньше лучше.

Для HDBSCAN сначала рассчитываются silhouette и DB **только среди назначенных точек**. Затем средний silhouette умножается на долю назначенных объектов $q$, а DB делится на $q$. Это заранее заданный штраф за шум: без него метод мог бы отбрасывать сложные объекты и получать искусственно хороший индекс. Для KMeans и спектрального метода $q=1$. В дальнейшем под $s(P)$ и $DB(P)$ понимаются именно эти оценки с поправкой на покрытие. В M0 выбирается максимум $s(P)$; в смеси используется $I_s(P)=(s(P)+1)/2$. Для DB максимизируются $-DB(P)$ и $I_s(P)=1/(1+DB(P))$. Эта нормировка задаёт шкалу смеси, но не является калиброванной вероятностью.

Частичная внешняя оценка на размеченном подмножестве L:

$$A_L(P)=\operatorname{ARI}(y_L,P_L).$$

Для таблицы сопряжённости $n_{ab}$ обозначим $U=\sum_{ab}\binom{n_{ab}}2$, $V=\sum_a\binom{n_{a\cdot}}2$, $W=\sum_b\binom{n_{\cdot b}}2$, $N=\binom m2$. Тогда

$$\operatorname{ARI}=\frac{U-VW/N}{(V+W)/2-VW/N}.$$

Каждая точка с меткой HDBSCAN -1 при вычислении внешних метрик рассматривается как **отдельная неназначенная группа из одного объекта**. Объединять весь шум в один кластер было бы неверной семантикой. При bootstrap-кратностях повторения одной и той же шумовой точки сохраняют её собственный ID. В вырожденных случаях применяется соглашение sklearn: одинаковые тривиальные разбиения получают 1. Это может создать обманчивого лидера при крайне малой разметке, поэтому такие случаи отмечаются.

Для смеси ARI переводится в $A_s=(A_L+1)/2$. Это фиксированное преобразование шкалы, не калиброванная вероятность и не гарантия равной информативности двух слагаемых. Пакетный расчёт ARI через таблицы сопряжённости работает на NumPy или CuPy для всех кандидатов и bootstrap-повторов; выбор M0–M7 и запись результатов остаются на CPU, поскольку это малые массивы и логика управления.

## 5. Разметка, покрытие и неопределённость

Групповой случайный split с seed=31415 выделяет примерно 50% **групп** в T; доля объектов может отличаться от 50%. Остальное — S. Split постоянен во всех методах и повторениях.

Бюджеты m=20,50,100,200; 30 повторений, начальные seeds 1000,…,1029. Внутри сценария/повторения один порядок раскрытия меток даёт вложенные L: первые 20 входят в первые 50 и т.д. Одинаковое L получают все методы.

| Сценарий | Что делает симулятор |
|---|---|
| random | равномерная выборка объектов S без возвращения |
| missing_classes | случайно выбирает ceil(C/2) классов резерва, раскрывает метки только из них |
| biased | случайная половина классов получает вес 10, остальные вес 1; выборка последовательная без возвращения |

Симулятор знает скрытые классы S для построения условий эксперимента. Селектор получает только метки L и внутренние оценки. Истинное покрытие $|\{y_i:i\in L\}|/|\{y_i:i\in X\}|$ — **последующая диагностика**, не вход M6. Покрытие одинаковым числом меток не гарантируется.

В missing_classes может оказаться недостаточно объектов для максимального бюджета. Половина классов выбирается повторно, не более 1000 попыток. После этого условие записывается как неприменимое. Такой отказ нельзя скрывать. Повторный выбор создаёт условное распределение по допустимым половинам; число попыток сохраняется. Для настройки M4 пропуски запрещают заморозку результата.

### Bootstrap

B=200 общих bootstrap-выборок для всех кандидатов и методов в одном L. Единица — объект, а при нескольких размеченных объектах из одной группы — группа. Группа выбирается с возвращением, все её размеченные объекты повторяются вместе. При группах переменного размера число объектов в bootstrap-выборке меняется.

Кластеризация не пересчитывается. Пересчитывается ARI по повторно выбранным размеченным объектам. Реализация использует целочисленные кратности в таблице сопряжённости; это эквивалентно физическому повторению строк, а не коррекции смещённой разметки весами вероятности включения. Независимого bootstrap пар документов нет: пары зависимы.

## 6. Восемь правил выбора

Пусть $P_0=\arg\max_P A_L(P)$ с разрешением равенств по каноническому ID. Численный допуск равенства $10^{-12}$.

| Метод | Правило |
|---|---|
| M0 | Максимум I без использования внешнего качества |
| M1 | Максимум частичного ARI; равенства по ID |
| M2 | Максимум I среди кандидатов, равных внешнему максимуму |
| M3 | Максимум $0.5 I_s+0.5 A_s$ |
| M4 | Максимум $(1-\lambda)I_s+\lambda A_s$; lambda заморожена на development |
| M5 | Максимум I среди $A_L(P_0)-A_L(P)\leq\tau$, основной tau=0.05 |
| M6 | Максимум I среди кандидатов с разностью не больше адаптивного допуска |
| M7 | Максимум частоты победы по внешнему ARI в bootstrap; равные победители делят голос |

Для M6:

$$d_P=A_L(P_0)-A_L(P),\qquad d_P^{(b)}=A_{L^{(b)}}(P_0)-A_{L^{(b)}}(P),$$

$$\hat\sigma_P=\operatorname{sd}_{b=1}^{B}(d_P^{(b)}),\qquad
\mathcal E_c=\{P:d_P\leq c\hat\sigma_P+10^{-12}\},$$

$$\hat P_6=\arg\max_{P\in\mathcal E_c}I(P).$$

Лидер $P_0$ фиксируется по исходному L и **не меняется** внутри расчёта bootstrap-разностей. Стандартное отклонение оценивается с ddof=1. Используется разброс **парной разности**, а не сумма независимых дисперсий ARI. Основной c=1. Значения 0.5 и 2 — анализ чувствительности.

Это эвристика выбора. Множество $\mathcal E_c$ не является доказанным доверительным множеством; c=1 не означает уровень значимости или 95%-покрытие. Bootstrap условен относительно наблюдённых классов и не восстанавливает пропущенные темы. Выбор лидера по тому же L также влияет на статистические свойства.

### Настройка M4

Lambda ∈ {0,0.25,0.5,0.75,1}. Для каждого веса считается regret на скрытой проверочной части **development-синтетики**. Сначала усредняются повторения внутри сценария/бюджета, затем условия внутри набора, затем 18 наборов. При равенстве выбирается меньшая lambda. Один вес переносится на подтверждающую синтетику и реальные корпуса; перенос сам является проверяемым предположением.

### Fallback

Основная серия не заменяет внешнее правило даже при вырожденной разметке. Отдельный `text_fallback.nip` включает переход всех внешних правил к M0, если в L менее двух классов или нет ни одной одноклассовой пары. Сохраняется доля срабатываний. M4 в этой дополнительной серии отключён, поскольку основной замороженный вес настраивался без fallback.

## 7. Проверочная оценка

После выбора открываются метки T. Основная метрика $Q_T(P)=\operatorname{ARI}(y_T,P_T)$.

$$R(\hat P)=\max_{P\in\mathcal P}Q_T(P)-Q_T(\hat P).$$

Это потеря выбора относительно лучшего кандидата **того же пула**, а не относительно неизвестного глобального оптимума. Regret≥0; меньше лучше. Дополнительно сохраняются AMI (arithmetic), homogeneity, completeness, вероятность regret≤0.02 и частота regret>0.1.

Основные парные контрасты: M6 против M2, M4 и M5. Выигрыш M6 определён как $R(\text{baseline})-R(M6)$, поэтому положительное значение означает улучшение. M7 помогает отделить пользу геометрии от эффекта bootstrap-агрегации.

E4: для каждого кандидата сохраняются частичный ARI, ARI на всём S, их разность, bootstrap SD оценки и SD разности с лидером. Метки всего S используются только после выбора. На проверочных объектах отсутствовавших в L классов ARI считается отдельно, если там хотя бы два объекта и два истинных класса; иначе значение отсутствует, а не приравнивается нулю.

## 8. Гипотезы и интерпретация

H1: в части режимов малой случайной разметки M6 уменьшает regret относительно внешнего выбора и фиксированной смеси. H2: по мере роста информативной разметки польза геометрии уменьшается. H3: при неполном покрытии bootstrap может давать малый разброс и одновременно высокую внешнюю потерю.

Ожидаемый результат — карта условий полезности внутреннего индекса, а не гарантированный универсальный прирост. Отрицательный результат тоже содержателен: M2 или простая смесь могут оказаться достаточными.

Интервалы `paired_contrasts.csv` относятся к случайности получения разметки на фиксированном корпусе. Для синтетики `synthetic_contrasts.csv` сначала усредняет повторения, затем resample-ит независимые реализации внутри геометрической ячейки. Повторения разметки не превращают три реальных корпуса в множество независимых предметных областей. Макросреднее по трём корпусам описательное.

Базовый отчёт не вычисляет p-values. Перед подтверждающей проверкой значимости нужно заранее зафиксировать семейство сравнений и подходящий тест, при множественных тестах — поправку Holm. Не следует выбирать только интервалы/бюджеты, на которых результат оказался положительным. Детали границ реализации — в [limitations.md](limitations.md).
