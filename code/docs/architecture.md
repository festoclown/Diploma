# Архитектура

## Стадии

```text
NIP → параметры
       │
       ├─ download_data → raw records + источник/commit/hash
       ├─ download_models → локальные веса + commit/hash
       │
       └─ prepare_data → очищенные документы либо числовые X
                           │
                           └─ encode_texts → X текстов (только для текста)
                                                │
                                          build_candidates CPU/CUDA
                                                │
                                разбиения + внутренние индексы
                                                │
          скрытые метки → симулятор L → правила выбора → выбранные ID
                                                           │
                                             раскрытие проверочных меток
                                                           │
                                        regret и диагностические таблицы
                                                           │
                                                summarize_results
```

## Модули

| Модуль | Ответственность |
|---|---|
| config.py | NIP, расширение сеток, наследование, проверки параметров, ID датасета |
| downloads.py | Единственные сетевые операции: корпуса, snapshot модели; группировка заголовков |
| data.py | Очистка, дедупликация, подвыборка, генерация Gaussian-компонент, подготовленные артефакты |
| embeddings.py | Локальная загрузка SentenceTransformer, токенизация, нормировка, кеш |
| backend.py | NumPy/CuPy, PCA, общая матрица расстояний и векторные внутренние оценки |
| candidates.py | Кластеры и внутренние индексы; алгоритмам не передаются метки классов |
| sampling.py | Split по группам, получение L, групповой/объектный bootstrap |
| metrics.py | Пакетный ARI с кратностями объектов на NumPy/CuPy, sklearn-оценки на проверочной части |
| selection.py | Чистая логика M0–M7; без файлов, модели, скрытых меток и coverage |
| experiment.py | Общее условие для всех методов, выбор, затем внешняя оценка; аудит |
| tuning.py | Ровно 18 development-наборов, сравнение lambda, заморозка |
| reporting.py | CSV, парные интервалы, отдельная агрегация реализаций, графики |
| storage.py | JSON/JSONL/NPZ, хеши, фиксация среды, атомарная запись файлов |
| cli.py | Разбор CLI и явный вызов одной стадии |

Каждый скрипт в `scripts` защищён условием `if __name__ == "__main__"`. Импорт модуля не начинает скачивание или эксперимент. Установка пакета через `pip -e` нужна, чтобы тонкие скрипты видели `src/clusterization`.

## Разделение информации

Селектор `choose()` получает четыре массива: частичные внешние оценки, исходные внутренние оценки, внутренние оценки на фиксированной шкале, bootstrap внешних оценок. Он не получает имена сценариев, истинное покрытие, полные метки или оценки на T.

`experiment.py` играет роль организатора исследования и знает полные метки. Он сначала собирает решения всех методов на L, затем считает test-метрики и сохраняет диагностику. Это дисциплина интерфейсов, а не криптографическая изоляция тестовых данных. Полный файл меток лежит локально и доступен исследователю. Не используйте его для ручной донастройки после просмотра confirmation.

Объекты T участвуют в построении геометрии X и кандидатов; это разрешено трансдуктивной постановкой. Не следует описывать результат как оценку модели на полностью невиденных объектах.

## Расширение

Новое правило выбора удобно добавить в `selection.choose`, список допустимых методов и документацию. Оно должно получать ту же информацию и тот же пул. Новый корпус добавляется в явный загрузчик с идентификаторами, текстом, меткой и group ID. Новый эмбеддер должен иметь собственный snapshot и кеш; при изменении pooling/нормировки нужна отдельная спецификация, а не только новое имя.

Базовая реализация последовательная. Она не предназначена для конкурентной записи одинакового артефакта несколькими процессами. `.tmp` обеспечивает атомарную замену отдельного файла, но не межпроцессную блокировку целой серии. Параллелизм можно добавлять по независимым датасетам с раздельными каталогами.

## Точки для дальнейшего ускорения

1. Отдельный кеш bootstrap-таблиц для серий c/tau.
2. Потоковая запись диагностики для больших серий.
3. Блочный расчёт расстояний, если плотная матрица не помещается в память.

На CUDA числовые векторы, PCA, KMeans/HDBSCAN/Spectral, расстояния, силуэт, Davies–Bouldin и пакетный ARI выполняются на GPU. Метки кандидатов возвращаются на CPU для сохранения; M0–M7 и запись файлов обрабатывают небольшие таблицы на CPU. Разбиения CPU и CUDA могут отличаться. Сокращение B, изменение выборки для силуэта или сетки параметров меняют протокол.
